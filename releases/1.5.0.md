BCRHP 1.5.0 release notes
------------------------

- Implement full Local Government workflow for editing existing heritage site records
- Implement per-step edit toggles with snapshot/restore on cancel
- Add map to review/success page; fix map geometry not displaying after provisional shapefile upload (#333)
- Support map printing / PDF export on review page
- Provisional delete support: orphaned tile cleanup on update, photo-workbench provisional delete handling
- Fix duplicate construction actor type entry
- Fix common name not saving (#319)
- Split requirements page for new vs. update site workflows

**Spatial location / step 3**

- Rework geometry page: PID-based boundary fetch, override/bypass controls, existing geometry comparison (#267)
- Fix for updated shpjs library breaking shapefile uploads (#338)
- Pull full geometry from WFS for PID boundaries (#74)
- Reset heritage site map layer to use advanced styling

**Site address / step 2**

- Add BC Geocoder integration with dismissable popup (#334, #337)
- Make City field optional (#337)
- Remove postal code field (#305)

**Images**

- Ensure primary image is displayed first (#341)

**Supporting documents / step 10**

- Add check for unsaved data before proceeding (#329)
- Don't require document upload when editing an existing site (#266)

**Classification / step 8**

- Don't allow progression when form is partially filled

**Other**

- Validate and display Arches Core form errors on photo-workbench (local patch for core bug #12942)

- Fix lazy-load issue (pending upstream Arches Core fix)
- Add LG landing page updates (#314)

- Add and expand frontend unit tests throughout

**Dependency updates**

### 1. BEFORE UPGRADING (!!! IMPORTANT !!!)

1. Update the maintenance page with appropriate dates and details. Maintenance page is found at
   `/sw_ux/httpd0(1|2)/www/html/maintenance.html`
2. Put system into maintenance mode:

```shell
touch /apps_ux/apps_(dlvr|test|prod)/maintenance/bcrhp
```

3. Confirm system in maintenance mode by accessing:
   `https://(|dlvr|test)apps.nrs.gov.bc.ca/bcrhp`. System should not be live, and maintenance page should be displayed.

4. Backup database:

```shell
sudo -u wwwadm /bin/bash
cd /apps_ux/apps_[env]/backups/database
chmod 700 .
pg_dump -Upostgres bcrhp_[env] > 2026-09-08_bcrhp_pre_1.5.0.sql
gzip 2026-09-08_bcrhp_pre_1.5.0.sql
chmod 400 2026-09-08_bcrhp_pre_1.5.0.sql.gz
chmod 500 .
```

5. Backup source code:

```shell
sudo -u wwwadm /bin/bash
cd /apps_ux/apps_[env]/backups
mkdir 2026-09-08_bcrhp_pre_1.5.0
mv ../bcrhp 2026-09-08_bcrhp_pre_1.5.0/
mv ../bcrhp_test_venv 2026-09-08_bcrhp_pre_1.5.0/
```

### 2. Perform Application deployment

The source code branches are as follows in the `cd/docker/config/app_env` file:

```yaml
FORCE_CORE_PIP_INSTALL=True

CORE_REPO_TAG=v8.0.10-bcgov-4
COMMON_REPO_TAG=v2.0.14
CONFIG_BRANCH=v1.5.0
```

Ensure the ansible source branch is set properly in the `cd/docker/run_deployment.sh` file:

```shell
export ANSIBLE_BRANCH=main
```

The migration variables must be set as follows (empty line ensure migrations are complete):

```yaml
perform_migration: False
```

```bash
docker start bcrhp-deployer
cd/docker/run_deployment.sh <dlvr | test | prod>
```

### 3. Run migrations and reindex database:

```shell
sudo -uwwwadm /bin/bash
cd /apps_ux/apps_<env>
source bcrhp_<env>_venv/bin/activate
cd bcrhp
python manage.py migrate
python manage.py bc_reindex_database
python manage.py clear_mvt_cache
exit
 ```

### 4. Take system out of maintenance mode:

```shell
sudo -uwwwadm rm /apps_ux/apps_(dlvr|test|prod)/maintenance/bcrhp
```
